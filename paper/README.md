# TACZ Paper

本模块为 **Paper 1.21.11 / Java 21** 提供 TACZ 服务端逻辑。客户端使用本仓库构建的 **NeoForge 1.21.10 MOD / Java 21**。1.21.10 客户端连接 1.21.11 服务端仍需额外配置兼容的原版协议转换方案；TACZ 桥接不负责原版版本转换。TACZ 动作和菜单通过 `tacz:paper` Plugin Message 通道传输，桥接协议保持为 4。

## 支持范围

- 首次启动导出仓库默认枪包，之后从独立目录读取枪械、弹药、配件、兼容标签和工作台配方，支持多级子目录与新增物品 ID。弹药箱容量在 `config.yml` 配置。
- 服务端处理开火、弹药扣除、射速、拔枪、换弹、拉栓、射击模式、瞄准、热量、近战及配件参数。
- 逐 tick 弹道支持遮挡、实体穿透、距离伤害、头部/躯干/腿部判定、穿甲、燃烧和爆炸；伤害进入 Bukkit 事件。
- 客户端接入现有枪模、第一/第三人称渲染、背包和掉落物渲染、HUD、动画及声音。子弹模型、曳光和默认包拖尾由客户端复用原 MOD 渲染；Paper 继续逐 tick 计算弹道、碰撞和伤害。
- 命中方块显示弹孔、材质碎屑和声音；命中实体接入原 MOD 的准星、爆头/击杀音效及受击反馈。爆炸效果由服务端触发，不额外生成弹孔。
- 工作台由 `/tacz workbench` 打开 MOD 界面，不绑定或注册方块。改装按键 Z 和 `/tacz refit` 使用原 MOD 的枪械改装界面，保留枪械预览、配件槽、属性展示和可编辑激光颜色；弹药箱支持命令和右键。

外部配置沿用 TACZ 参数格式，但不直接导入任意第三方枪包 ZIP、执行任意服务端 Lua 或注册自定义方块、靶子矿车。默认枪包使用的服务端脚本行为由 Java 状态机实现，新增型号需使用已支持的机制。模型、贴图、动画、音效和显示资源仍由客户端枪包提供，服务器同步参数与物品索引；新增资源时也要更新客户端资源。Paper 不提供 Forge/KubeJS 的服务端事件及接口。

命中使用服务端简化部位体积：直立/潜行根据实体当前包围盒和眼睛位置生成；玩家趴下、游泳、鞘翅和激流姿态按身体朝向生成横向体积，游泳和飞行分别处理原点偏移。手臂归入躯干，不跟随手部动画。该模型不包含精确动画骨骼、Forge multipart 和历史命中补偿，姿态过渡与特殊生物模型仍可能有视觉偏差。爆炸使用径向伤害及 Bukkit 爆炸事件，方块破坏算法与原 MOD 不完全相同。

## 构建

两个模块各自使用自己的 Gradle Wrapper，分别管理 ModDevGradle 和 paperweight 的构建环境。IDE 可以单独导入 `paper/settings.gradle.kts`。

客户端：在仓库根目录使用 Java 21：

```powershell
.\gradlew.bat test build
```

插件：在 `paper/` 目录使用 Java 21：

```powershell
.\gradlew.bat test build
```

Linux/macOS 对应使用 `sh ./gradlew`。构建产物分别位于根目录 `build/libs/` 和 `paper/build/libs/`；客户端部署 `tacz-1.21.10-neoforge-1.1.8+neoforge.1.21.10.hotfix2.jar`，该 JAR 已包含内嵌依赖，不要部署 sources JAR 或旧 Forge 构建产物。

Paper 使用 [paperweight-userdev](https://docs.papermc.io/paper/dev/userdev/) 的 1.21.11 dev bundle，可直接引用 Paper API、CraftBukkit、Mojang 映射 NMS，产物标记为 `MOJANG_PRODUCTION`。当前逻辑主要使用 Paper API。

## 部署和首次使用

1. 将 `tacz-paper-*-paper-SNAPSHOT.jar` 放入 Paper 1.21.11 的 `plugins/`，使用 Java 21 启动。
2. 客户端安装 NeoForge 21.10.64 或同系列更新版和本仓库新构建的 MOD，保留默认枪包资源，配置好 1.21.10 → 1.21.11 原版协议转换后连接服务器。旧版未经桥接修改的 TACZ 客户端无法使用这些插件物品。
3. `/tacz status` 显示客户端桥接“已就绪”后，由 OP 或控制台发放物品。当前使用桥接协议 **4**，以 PDC 的类型与型号 ID 识别物品，必须同时更新客户端和插件；协议 1/2/3 的旧版本不能与新版本混用。
4. 玩家使用原 TACZ 按键射击、换弹、瞄准和改装；使用插件工作台命令制作物品。

例如：

```text
/tacz give Steve gun tacz:ak47
/tacz give Steve ammo tacz:762x39 128
/tacz give Steve attachment tacz:ammo_mod_fmj
/tacz ammobox Steve 1
/tacz workbench
/tacz refit
/tacz supplies
```

插件发放的枪默认未装弹。真实背包中的物品始终是原版载体，禁止用客户端创造栏的原生 MOD 物品替代插件发放物品。

射速沿用枪包参数（默认 AK-47 为 600 RPM，即每发约 100ms）。客户端按本地计划发送射击请求，服务器回执不重新延长下一发冷却；服务器只暂存一条提前不超过 50ms 到达的请求，到期重新检查枪械和玩家状态。网络或 tick 的短暂抖动不会直接丢掉这一发，也不会补发长时间卡顿期间积累的射击。弹药、伤害及射速上限仍由插件判定。

弹匣或膛室供弹枪的本地枪声、枪口动画和后坐力随客户端计划播放，连发组内也按枪包间隔安排。服务端开火回执携带请求序号与组内索引，已播放的本地效果不会再次播放；拒绝或中断会取消未发生的后续效果。直接从背包供弹的武器暂时仍等待服务端确认后播放。弹量快照仍由插件同步，命中提示、弹孔和伤害不在客户端预测。其他玩家的开火效果继续根据服务端事件播放。

常规状态每 2 tick 同步一次（20 TPS 时约 100ms），处理动作后会立即同步；连发实际击发的 tick 也会同步弹量与射击水位，避免客户端把同一发的消耗重复扣入临时显示。

换弹期间可以跳跃。实际装填阶段会暂停疾跑，进入收尾阶段后允许疾跑。普通整弹匣换弹不会因尝试疾跑或开火而被取消；支持逐发装填中断的枪械可提前收尾，已经装入的弹药保留。切换或丢弃枪械仍会终止当前换弹。

按 Z 打开原生改装界面后，从背包选择兼容配件进行安装或卸下。枪械预览和颜色调节在客户端显示，物品增减及最终颜色由插件校验并保存。安装、卸下后的服务器回执更新当前界面，不重置选中的配件槽；关闭界面或换枪后，迟到回执不会重新打开窗口。此改装更新需要同时替换客户端 MOD 和插件。

## 命令和权限

命令提供 Tab 补全，ID 可省略 `tacz:` 前缀。`give` 和 `ammobox <玩家>` 的发放目标必须在线且桥接就绪。

| 命令 | 用途 | 权限 / 默认 |
| --- | --- | --- |
| `/tacz help` | 查看帮助 | 所有人 |
| `/tacz status` | 查看插件和桥接状态 | `tacz.status` / 所有人 |
| `/tacz list <gun\|ammo\|attachment\|box> [页码]` | 分页查看可用 ID | `tacz.list` / 所有人 |
| `/tacz give <玩家> <类型> <ID> [数量]` | 发放枪械、弹药、配件、弹药箱 | `tacz.give` / OP |
| `/tacz supplies` | 箱子菜单领取主手枪械适配的弹药和配件 | 仅 OP 玩家 |
| `/tacz workbench` | 打开工作台 | `tacz.workbench` / 所有人 |
| `/tacz refit` | 改装手持枪械或卸下弹药 | `tacz.refit` / 所有人 |
| `/tacz ammobox` | 打开手持弹药箱 | `tacz.ammobox` / 所有人 |
| `/tacz ammobox <玩家> [等级 0–2]` | 发放普通、金或钻石弹药箱 | `tacz.ammobox` + `tacz.give` / OP |
| `/tacz reload` | 校验并重载目录配置，向客户端重新同步 | `tacz.reload` / OP |

`tacz.use` 控制枪械使用，默认所有玩家；`tacz.admin` 包含以上权限节点，默认 OP。`supplies` 单独检查 OP 身份，授权 `tacz.admin` 或通配权限不能让非 OP 使用。工作台和改装界面使用玩家背包中的实际材料，物品数量和兼容性全部由服务器检查。满背包时多余产物掉落在玩家处并设置拥有者。

OP 主手持有插件枪械后执行 `/tacz supplies`，打开原生箱子补给菜单。普通左键或右键点击弹药/配件领取 1 个；Shift 点击弹药领取一整组，数量遵循该弹药的堆叠上限（例如 7.62×39 为 60），Shift 点击配件仍领取 1 个。配件同时按枪械支持的槽位和兼容标签筛选，过多时可翻页。菜单打开期间更换枪械、失去 OP 身份或重载插件后不能继续领取。

## 配置

首次启动生成 `plugins/TACZ/config.yml`：

- `ammo-box.capacity.0/1/2`：新建普通/金/钻石弹药箱容量，默认 192/384/768。已有箱子保留创建时容量；同一箱子只存放一种弹药，清空后可换种类。
- `gameplay.max-active-bullets`：同时模拟的子弹上限，默认 8192。
- `gameplay.ignite-blocks`：燃烧弹是否能点燃方块，默认 false。
- `gameplay.ignite-entities`：是否允许枪包中的点燃实体效果，默认 true。
- `gameplay.explosion-block-damage`：是否允许具有破坏属性的弹药破坏方块，默认 false。
- `gameplay.explosion-knockback`：是否允许爆炸击退，默认 true。

首次启动会将默认条目导出为独立 JSON 文件。每个分类递归读取 `.json` 文件，下面展示一种自行整理后的目录结构：

```text
plugins/TACZ/
├─ config.yml
├─ guns/
│  └─ tacz/rifles/ak47.json
├─ ammos/
│  └─ tacz/rifle/762x39.json
├─ attachments/
│  └─ tacz/scopes/scope_standard_8x.json
├─ attachment_tags/
│  └─ tacz/scope.json
├─ recipes/
│  └─ tacz/gun/ak47.json
└─ .pack-files-v1
```

子目录只用于整理文件，物品身份由文件中的 `id`（例如 `tacz:ak47` 或 `custom:rifle_a`）决定。可直接移动、重命名文件，不能在多个文件中重复定义同类 ID。默认配置只在首次初始化时补齐，之后不会覆盖用户修改，也不会自动恢复已删除的条目。

| 目录 | 每份 JSON 的字段 | 用途 |
| --- | --- | --- |
| `guns` | `id`、`index`、`data`、`allow_attachments` | `index` 定义名称、显示资源、分类；`data` 定义伤害、射速、弹容、装填等；`allow_attachments` 定义兼容配件 ID 或 `#标签` |
| `ammos` | `id`、`index` | 弹药名称、显示资源、堆叠数等 |
| `attachments` | `id`、`index`、`data` | 配件类型、显示资源、属性加成 |
| `attachment_tags` | `id`、`values` | 可复用的配件分组，`values` 包含配件 ID 或其他 `#标签` |
| `recipes` | `id`、`recipe` | 工作台合成配方，`recipe` 保留原 `materials`、`result`、`type` 结构 |

例如修改 AK-47 时，直接编辑导出文件中的 `data.rpm`、`data.bullet.damage`、`data.ammo_amount` 等字段；存在 `data.bullet.extra_damage.damage_adjust` 时，应同时调整距离伤害各档。原枪包字段完整保留在 `index`/`data` 内。加载器会为每个物品生成独立的数据索引，`index.data` 无需手动维护。当前支持 `reload.type` 为 `magazine` 或 `inventory`，逐发换弹沿用默认枪包的受支持脚本机制。

新增型号可复制同机制的现有文件，更换 `id`、名称和参数，并引用客户端已有的 `index.display` 资源；新增弹药时同步修改枪械的 `data.ammo`。物品直接以 `kind` 与 `id` 识别，不需要配置 CMD 或分配模型编号。插件不再生成、读取或修改 `model-mappings.json`；旧文件即使存在也会被忽略。

修改完成后使用 `/tacz reload`。插件先校验所有文件、引用与同步包大小，全部通过后才替换运行中的枪包并向在线客户端重新同步；失败时命令/日志给出错误，保留原枪包。删除型号时需一并处理引用它的枪械、配方或标签。启动时没有可用旧配置，错误会阻止插件启用。

现有物品仍按新配置校验：降低弹容前先退弹，删除射击模式前将旧枪切到保留的模式，禁止或删除配件前先从旧枪拆下。删除型号或改变 `id` 会使对应旧物品失去定义；本次没有加入跨背包、容器和离线玩家的物品迁移。普通伤害、射速等数值调整无需重新发枪。

### 命中部位与伤害倍率

直接子弹命中分为 `head`（头部）、`torso`（躯干，含手臂）、`legs`（腿部）。每段弹道选择最先进入的区域和最近实体，墙体仍会截断检测；先碰到腿或身体时，不会再把同一实体后方的头部算成爆头。近战与爆炸范围伤害沿用各自原有计算，不套部位倍率。

枪械 JSON 中的 `data.bullet.extra_damage.head_shot_multiplier` 继续决定爆头倍率，配件对该倍率的修改仍生效。可以在同一个 `extra_damage` 对象内添加：

```json
"body_part_multipliers": {
  "torso": 1.0,
  "legs": 0.75
}
```

这只是新增字段，保留原有 `armor_ignore`、`damage_adjust` 等内容。躯干/腿部未配置时均为 `1`，不自动改变原有普通命中伤害；各倍率允许 `0–100` 的有限数字。最终先按距离计算基础伤害，再乘所中部位的一个倍率，随后进入穿甲与 Bukkit 伤害流程。客户端继续使用原来的爆头/普通命中反馈，腿部不额外播放专属音效。

`config.yml` 的 `hitboxes` 控制区域形状，支持 `/tacz reload`：

```yaml
hitboxes:
  default-profile: generic
  profiles:
    humanoid:
      head-width: 0.85
      head-height: 0.25
      legs-height: 0.45
    generic:
      head-width: 0.85
      head-height: 0.25
  entities:
    minecraft:player:
      profile: humanoid
    minecraft:zombie:
      profile: humanoid
      legs-height: 0.42
    minecraft:slime:
      profile: body
```

- `humanoid`：头、躯干、腿三分区。玩家、僵尸/骷髅系列、村民、灾厄村民、猪灵、末影人和盔甲架默认使用此规则。
- `generic`：有界的眼高头部区域和其余躯干，头部向实体身体朝向的前侧定位，不给四足动物强加人形腿部区间。
- `body`：整体按躯干处理。史莱姆、岩浆怪、蜘蛛/洞穴蜘蛛、潜影贝、鱿鱼/发光鱿鱼、恶魂、悦灵和恼鬼默认使用此规则。
- `head-width` 是头部相对身体的宽度比例，`head-height` 是头部沿身体长轴的比例，`legs-height` 是腿部占身体长轴的比例；实体条目可以单独覆盖这些值。直立头部同时受眼高和实际实体箱约束。

未写入旧 `config.yml` 的设置会使用上述内置默认值。区域配置、枪械倍率与目录数据先校验再重载，非法数值或未知实体/规则会阻止本次重载，保留当前可用配置。

## 物品与通信

`shared/` 提供两端共用的消息编码、物品身份解析和分片逻辑。登录流程为 `hello → welcome → pack → ready`：先校验协议，再同步服务器加载的枪包参数与物品索引，最后启用玩法。同步包不再携带 CMD 编号映射。单消息不超过 30,000 字节；分片带 SHA-256，限制压缩/解压大小。动作带单调序号并限频，菜单交易还校验会话令牌、槽位、物品实例、距离和权限。

弹道使用独立的 `ballistics` 消息，每名观察者按 tick 合并生成、结束、命中及低频校正记录。每批最多 128 条记录，同时受 30,000 字节上限限制，超限分包，保持事件顺序。客户端根据初始位置、速度、重力和阻力自行推进展示，不上传子弹位置或命中结果；服务端在命中处终止可视弹体。批次携带真实维度标识，切世界、断线和重新握手清理旧展示状态。子弹附近的观察者可收到中途状态快照，不需要逐 tick 广播每颗子弹的位置。

载体分别为木棍、纸、燧石和箱子，身份和状态保存在 `tacz:bridge` PDC 的 JSON 中。`kind` 区分枪械/弹药/配件/弹药箱，`id` 对应服务器目录中的型号；枪械和弹药箱以 `instance` UUID 区分实例，弹药和配件无需每件独立 UUID，因此可以正常堆叠。弹药、膛室、配件、射击模式、热量和颜色仍保存在物品上。

客户端读取标签后校验型号是否在当前同步目录中，并创建临时 MOD 物品视图，通过枪械 ID 和显示资源加载模型。枪械发放和渲染均不要求 `CustomModelData`；即使物品有其他插件设置的 CMD，也不会影响 TACZ 身份识别，TACZ 写入状态时不改动这个可选外观字段。仅有 CMD 而无有效 PDC 标签的普通物品不会成为枪械。两端共用类型、型号、载体和实例校验；服务端继续验证堆叠数量、弹量、配件兼容性等权威状态。真实网络与背包中的 ItemStack 仍是原版载体。

动作通过消息同步。换枪、死亡、离线、跨世界和重新握手清理临时动作状态；弹药、配件、枪内热量及箱内弹药保存在物品上。原版合成、烧炼、铁砧等变换路径会保护插件物品，普通容器储存和移动仍可使用。
